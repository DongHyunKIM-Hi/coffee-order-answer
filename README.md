# 1단계 — 정상 경로

> [!NOTE]
> 과제의 **모범 답안**입니다. 정답은 하나가 아니며, 좋은 구현의 한 예시입니다.
> 단계는 커밋으로 나뉘어 있습니다: `step1`(정상 경로) → `step2`(예외 처리) → `step3`(최종). `git checkout`으로 오갑니다.
>
> 이 단계에서 `bash check-scenarios.sh`를 돌리면 **5/12**가 나옵니다. 고장이 아니라 설계대로입니다 — 기능(메뉴·충전·주문·인기 메뉴)은 돌아가지만 예외 처리, 트랜잭션, 동시성, 인기 메뉴 7일 범위가 아직 없습니다.
해설 영상용 단계별 코드의 첫 단계입니다. 단계 구분과 실측 결과는 `docs/stages.md`에 있습니다.

- **만드는 것**: 메뉴 목록 조회, 포인트 충전·조회, 주문과 결제, 인기 메뉴 조회. 네 API가 MySQL로 동작합니다.
- **일부러 하지 않는 것**: 입력 검증, 에러 응답 형식, 잔액 확인, 트랜잭션, 데이터 수집 플랫폼 전송,
  인기 메뉴의 7일 범위, 동시성 제어. 각 자리에 왜 그런지와 몇 단계에서 채우는지를 주석으로 적어 두었습니다.

```bash
docker compose up -d --wait   # MySQL 8.4 (3306), Redis 7.4 (6379)
./gradlew bootRun             # 8080
```

- 1단계는 Redis를 쓰지 않습니다(3단계에서 분산 락과 인기 메뉴 집계에 씁니다).
- `schema.sql`, `data.sql`, `build.gradle`, 패키지 구조는 3단계(`step3` 커밋)와 같습니다.
- 테스트 코드는 없습니다. 테스트는 3단계에서 다룹니다.
